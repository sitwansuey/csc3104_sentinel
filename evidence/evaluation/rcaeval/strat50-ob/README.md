# RCAEval stratified 50-case run (sample-strat50-ob)

This is an **exploratory** result, not the pre-registered
[sample-ob-v1 protocol](../../../../docs/evaluation/rcaeval/PROTOCOL.md): there
is no freeze file, no baseline was run on the same cases, and the first ten
cases guided development. `report.json` and `report.md` were generated by
`scripts/evaluation/rcaeval_report.py` from the committed bundle
`evidence/2026-11-20/rcaeval-ob-strat50-sentinel-r2`:

```powershell
python scripts/evaluation/rcaeval_report.py --results evidence/2026-11-20/rcaeval-ob-strat50-sentinel-r2 --out evidence/evaluation/rcaeval/strat50-ob
```

## Sample

[`docs/evaluation/rcaeval/sample-strat50-ob.json`](../../../../docs/evaluation/rcaeval/sample-strat50-ob.json)
lists the 50 Online Boutique cases, 25 from RE1 and 25 from RE2. A stratum is
one suite and fault type: RE1 keeps cpu, delay, disk, loss and mem; RE2 keeps
cpu, disk, loss, mem and socket (a seeded hash order left out RE2 delay). Each
stratum holds every one of the five root-cause services once, with the
repetition chosen by a seeded SHA-256 hash. No prediction influenced the draw.

- **dev (10 cases, seed 3104):** one service per stratum. These cases were
  used while fixing the diagnosis tools (healthy-only baselines, dated trace
  timestamps, explicit empty windows and the Reporter support gate).
- **eval (40 cases, seed `3104|ext20`):** the other four services of each
  stratum, drawn after development and run with the code unchanged.

## Method and versions

Sentinel's RCA agent through the benchmark adapter (`--method sentinel`):
`qwen3:14b` (Q4_K_M) on local Ollama, seed 42, at most three rounds and 16
tool calls, a 300 s model-call limit and 1,200 s per case, abstention allowed.
`run.json` and `versions.json` in the bundle record the configuration, package
versions and model digest. The code is commit `7220856` (inferred: the runs
used that tree before it was committed; the eval part matches it exactly, and
the dev part lacks only a one-line abstain fix that no dev case triggered).

## Result

Service-level AC@1 **0.78** (39 of 50; 95% Wilson interval 0.648 to 0.872),
against a Chance@5 of 0.24. RE2 (metrics, logs and traces) scored 0.88 and
RE1 (metrics only) 0.68; dev 0.80 and eval 0.775. By fault: disk 1.0, socket
1.0, mem 0.9, cpu 0.8, delay 0.6, loss 0.4. The agent returns one service, so
AC@3, AC@5, Avg@5 and MRR equal AC@1, and indicator-level AC@1 is 0. An earlier
version of the adapter, whose metric baseline included the faulty samples,
scored 0.10 on the ten dev cases.

## Deviations

- **Not pre-registered.** No freeze file or prompt hash; the sample was chosen
  for this run, and the dev cases informed the code that was evaluated.
- **Run status FAILED.** One case (`re1ob_currencyservice_cpu_1`) errored when
  the Reporter call exceeded the 300 s limit, and again on a seeded retry. It
  is scored as a miss; FAILED is not an accuracy threshold.
- **Dirty tree.** Both parts ran on uncommitted code later committed as
  `7220856`; provenance is inferred.
- **Two parts merged.** The dev and eval parts ran separately with
  `scripts/evaluate_rcaeval.py` and were merged and rescored; the summary was
  rewritten in the `rcaeval_run.py` format so this report can read it.
- **No baseline.** BARO and anomaly ranking were not run on these cases, so
  there is no paired comparison and no comparison with the paper.
- **Token counts redacted.** The evidence sanitiser removes the usage
  token-count fields from the scores summary by design.

## Interpretation

Sentinel's agent localises resource faults (disk, socket, memory, CPU) well on
this sample, but network faults much less well: seven of the eight wrong
answers were delay or loss faults, where the added latency also shows in
neighbouring services and the agent named one of them. Two abstentions were
appropriate or cautious: one case has no metrics inside its window. With 50
cases, at most ten per fault, the intervals are wide; read them, not the point
values, and do not claim Sentinel beats another method without a paired run.
